Asymptotic Complexity & Proofs

Formal analysis of time, space, and optimality conditions.

1. Why Huffman is Optimal: Greedy Choice Property

Let $x$ and $y$ be the two characters with lowest frequencies in alphabet $C$. There exists an optimal prefix code for $C$ in which $x$ and $y$ are sibling leaves at maximum depth.

B(T) = ∑ [f(c) × dT(c)] — Cost function minimized via Min-Heap merge.

Proof via Exchange: Swapping higher-frequency nodes with $x, y$ at deepest positions reduces total weighted path length, guaranteeing greedy optimality.

How Compression Works & Container Specification

Design and Analysis of Algorithms Compressor Container Specification

When you compress a file or image, it keeps its original file extension with a compressed_ prefix (e.g. compressed_photo.png or compressed_notes.txt). For lossless algorithmic bitstreams, it embeds a standardized binary header so decoders know which algorithm was used and how to reconstruct the exact original file.

Standard 50-Byte Fixed Binary Header:

Offset (Bytes) Field Name Type Purpose
00 - 03 Magic Identifier 4-byte ASCII (DAAC) Guarantees file identity (0x44 0x41 0x41 0x43). Rejects foreign files.
04 Format Version uint8 (0x01) Container protocol version for backward compatibility.
05 Algorithm ID uint8 (1, 2, or 3) 1 = Huffman Coding, 2 = PackBits RLE, 3 = LZW Compression.
06 - 13 Original Size uint64 Big-Endian Expected uncompressed byte count for exact buffer sizing.
14 - 45 SHA-256 Digest 32-byte Binary Hash Cryptographic fingerprint of original data for 100% lossless verification.
46 - 49 Metadata Length uint32 Big-Endian Byte length of auxiliary payload (e.g., Huffman frequency table).
50 ... End Payload Stream Variable Bitstream The compressed algorithmic payload bitstream.
💡 Lossless Integrity Guarantee: Because every .daac archive embeds the original file's SHA-256 cryptographic digest, the decompressor automatically validates that the restored file is 100% bit-for-bit identical before rendering it.
